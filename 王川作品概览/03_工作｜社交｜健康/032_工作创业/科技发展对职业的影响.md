# 技术与权力

技术是知道如何做某件事；

权力结构是知道必须做哪些事才能移动到食物链的高端；

权术就是寻找权力结构对自己有利的切入场景发力，避免在对自己不利的场景做低效或无用的消耗，持续迁移到食物链的高端。

---

高科技带来的权力结构的改变，很多看起来很热闹，但转瞬即逝，非常不稳定。技术本身没有那么重要，技术背后的权术，才是关键。这个权术，在于理解足够多关键技术细节，可以把权力结构中稳定甚至不断强化的那部分，和大部分昙花一现的表象区分出来。

懂再多技术细节，但不关注权力结构，无法把权力结构搞清楚，本质就是浪费时间学了很多驴唇不对马嘴的东西。这种人看似兢兢业业，忙忙碌碌，但在工作中、市场中、投资中始终处于食物链下端。

---

OpenAI 虽然在 LLM 领域有开创性的地位，但正如微软 CEO 所说：「OpenAI 即使明天消失，也没有关系……我们有人，有算力，有数据……我们在他们上面，下面，和周边。」

Sam Altman 虽然不是技术开发者，也号称没有 OpenAI 的股份，但却利用 OpenAI 的影响力去全世界融资，做别的项目，比如发币 Worldcoin，赚得盆满钵满。而其他技术人员如 Ilya、Greg，在技术开发和部署上，确实做出了重大贡献。但在科技圈之外，在真正出钱的那些土豪圈里，又有谁知道他们呢？

# 标准化消灭系统⼯程师的职位

1/ 很多⼈听到所谓「系统⼯程师」(system engineer) 这个词，会⼀头雾⽔，不知道这是什么玩意。

2/ 电脑⾏业的早期，不同零部件之间的界⾯各不相同，CPU 接受键盘指令时，还要具体分析键盘上第⼏⾏第⼏列的键被按了，来判断是哪个字⺟。这时就需要系统⼯程师根据不同⼚商的设备的界⾯来写相应的代码，反正就是⼀些很⽆趣琐碎的脏活。

3/ 微处理器更便宜后，后来的键盘内部有个小的芯⽚，直接给 CPU 发⼀个标准化的信息，某某字⺟被按了。界⾯简单而标准，以前的系统⼯程师⼲的脏活不需要了。

4/ 类似的，以前的电脑从磁带⾥读数据，还要发指令控制磁带转动的速度和磁带的张⼒，启动或停⽌磁盘，来读写数据。不同⼚商的标准不⼀的边缘设备的控制和整合耗费⽆数系统⼯程师的精⼒。

5/ 现代 CPU 从硬盘⾥读数据指令就简单多了，不需要知道底层物理细节，只要发⼀个标准化的指令给硬盘，「到某某区给我把数据调出来」，就好了。

6/ 这种市场⾃发[[涌现]]的标准化的各个设备之间沟通的抽象的界⾯，⼤⼤提⾼效率，⼀下⼦把很多繁琐低效的系统⼯程师的职位消灭了。才有了 PC（个⼈电脑）⾏业的迅猛进步。

7/ 可以隐约地感到，这种标准化、统⼀化、抽象化的发展，将要延伸到社会的各个层⾯，消灭掉各种繁琐、标准不⼀、效率低下的信息交互沟通⽅式，消灭掉各种类似的⼲⽆趣脏活的「系统⼯程师」的职位，建⽴更多统⼀简洁的界⾯，极⼤提⾼社会运转的效率。

# 在社交媒体时代为什么还需要记者

在社交媒体时代，为什么还需要记者？

如果当事⼈可以直接和听众迅速反复地沟通，记者能够增加什么价值？

很多记者没有意识到，⾃⼰的传播渠道缺乏有效真实即刻的[[设计自己的反馈机制|反馈]]，实际影响⼒在迅速衰减。但⼤公司的招牌带来的影响⼒的幻觉和优越感，挥之不去。

各种各样的中间⼈、中间商，如果不能保持较⼤的效率上的优势，最终都会变得⽆关紧要而被绕过去。

# 把多次重复使⽤作为指导⾏为的原则

要把「多次重复使⽤」作为指导⾃⼰⾏为模式的重要原则。每次要解决那种⼀次性的问题，就会觉得很烦。「重复使⽤」包括，在分析问题时，多研究底层机制和主要⽭盾，不浪费时间在表层泡沫的随机波动。然后你会发现，若⼲年前弄清楚的底层机制，现在仍然管⽤，迅速看清问题本质。

很多媒体⼯作者，天天追逐各种表层的热点泡沫，但⽆法复⽤，每天很累很⾟苦，但其实⼯作价值不⾼。如果真正能够坐下来把底层机制原理弄清楚了，⼤概知道在什么阶段会出现什么现象，什么东西是真正⾼价值的，就可以⼤部分时间对外界信号⽆动于衷，让⾃⼰轻松很多。

可以这么说，你的「痛苦指数」，很⼤程度上取决于你有多⼤⽐例的时间要被迫处理各种⼀次性的⽆聊琐事和⼯作。但看似再⽆聊或者枯燥的事情，如果做⼀次，以后可以⻓期多次受益，它就不再⽆聊枯燥。

软件公司的⾼估值，很⼤程度上就是来⾃这种层层叠加的「重复使⽤」。DNA 就是⽣命体在地球上重复使⽤⼏百亿，⼏千亿次不断叠加[[演化]]出来的复杂软件。

为什么那么多公司热衷于开拓全球市场，把东西卖到更多的客户⼿⾥？⽆它，就是增加重复使⽤的频率，分摊固定成本，提⾼利润率。不这样做的公司，早就死了。

经济发达的国家，背后⼤多有个庞⼤开放的⾃由贸易体系，可以让其销售货物和服务，增加劳动成果被复⽤的频率，也就增加利润率和劳动者的⽣活⽔平。

# 美好未来，注定并不连续

1/ 奋⽃中的⼈们会有⼀个幻觉，就是美好的未来，对⾃⼰是连续的：换⾔之，⼈们会认为，只要⾃⼰不断努⼒埋头⼲，攒的钱越多，就越接近美好的未来。

2/ 但实际情况并⾮如此，原因主要有⼆：第⼀，很多⾏业可能会突然出现向上的爆发式增⻓，和向下的迅速崩塌，这两种情况都是不连续的。错过前者，或者撞上后者，都会有巨⼤的差别。

3/ 第⼆，从⻛险管理⻆度看，即使统计上有看似极⼤的回报，但是如果某个⾏为⽅式有全军覆没的概率（⽐如⾼杠杆的⾦融投机被平仓，或者⻓期熬夜积劳成疾突然猝死），虽然你⼤部分时间可能赚得盆满钵满，但迟早⼀次撞上就可以把过去很⻓时间的积累全部抹杀，而让你彻底出局，⽆法继续参加游戏。如果有彻底出局的⻛险，所有的回报和概率的讨论将毫⽆意义。

4/ 这种连续的幻觉⾮常顽固，如果没有亲⾝经历或⽬睹上述不连续的跳跃，⼤部分⼈对这种说教会嗤之以⿐。

5/ 西班⽛帝国靠⼤航海起家，崛起来⾃于新⼤陆的发现，其早期发财套路就是奴役当地印第安⼈和⾮洲⿊奴开采美洲的⾦矿银矿。其中⼀个转折点是 1546 年在墨西哥和玻利维亚等地发现特⼤规模银矿，⼗六世纪西班⽛的⽩银储备相当于 1990 年等值的⼀万五千亿美元。挖矿利润⾼⻛险低，但后果就是⼤家不去真正发明创造，导致西班⽛通胀率⾼，除了⽩银外，什么都贵，把脏话累活外包给别⼈去⼲。其⼒量的顶峰，⼤约在 1588 年⽆敌号舰队被英国⼈摧毁之前。此后每况愈下，破产数次，甚⾄⼗九世纪初⼀度被拿破仑吞并。

6/ 奥斯曼⼟耳其帝国依靠严密的组织能⼒，在⼗五世纪控制了亚⾮欧三⼤洲的咽喉要道，尤其是彻底控制了红海和⿊海的交通运输。其发财套路主要是对经过贸易通路的商⼈课以重税，但同时也直接导致了欧洲⼈向南走⾮洲，向西走美洲，开辟新的贸易通路。其⼒量的顶峰⽌于 1566 年 Suleiman the magnificent 的去世。此后⼟耳其始终未能摆脱⽼套路，⽆法追赶⼯业⾰命的脚步，不断被欧洲列强挤压⽣存空间，直到⼀战之后被彻底肢解。

7/ 微软在九⼗年代初逐渐形成了桌⾯电脑操作系统的事实上的[[垄断，稀缺和财富的关系|垄断]]，并且利⽤它对分发渠道的牢牢控制，不断蚕⻝各类应⽤软件的市场，其相对⼒量的顶峰⼤约在 2000 年初。但同时也导致内部员⼯缺乏危机感和创新的动⼒，严重的 PC [[回报递增，路径依赖|路径依赖]]，完全错过了后来的搜索和移动互联⽹的市场。

8/ 通⽤电⽓九⼗年代后期的成⻓，很⼤程度上依赖于⾦融⼯程，本质上是⼀个假扮成⼯业集团公司的次贷银⾏。很⻓时间内很多⼈在这个套路上尝到极⼤甜头，越玩越⼤。但 2008 年次贷危机时通⽤电⽓差点因流动性危机破产。后⾯⼗年它并⽆实质性的内部⾰新，继续⽼套路，试图以各种收购兼并、[[股票回购]]的资本运作⽀撑股价，掩盖其内在的⼯程技术上的没落和战略眼光的缺失。GE Power 2018 年⼗⽉因为商誉受损（goodwill impairment）⼀次性减记两百⼆⼗亿美元。其股价现在回到 1995 年初的⽔平，并再次⾯临流动性危机的谣⾔冲击。

9/ 当某个⾏为套路对于某个公司或组织是⾏之有效的时候，这种套路将会不断被群体推进到极致，以获得更⾼的回报，这⾮常⾃然，不以个⼈意志⼒为转移。这种系统性套路，往往是各种偶然因素堆积在⼀起形成，相对于其它潜在竞争者建⽴起系统性的优势，在市场早期成⻓时期可能会有⼀个指数增⻓的过程，拉⼤和其他⼈的差距。

10/ 潜在的⻛险是，把套路推向极致的过程，是⼀个优化聚焦认知和特殊技能的过程，导致公司内部⼈事架构、个⼈的思考⾏为习惯，对这种系统性套路的极度依赖，⽆法摆脱，同时对于其它领域⾏业逐渐丧失感知⼒和相应的专业能⼒。

11/ 任何套路的演化，最终都会遇到⼀个[[阈值|临界点]]，因为市场的饱和、竞争者的涌⼊等等原因，沿着⽼套路继续投⼊，回报下降，接近于零，甚⾄变负。

12/ 之后，可能会有⼀个新的挑战者慢慢以完全不同的套路超越⽼的领先者。新⼈开始看上去体量很小，但是具有前瞻性的资本市场可能很早就赋予新的挑战者和⽼的领先者⼀样甚⾄更⾼的市值。当⽼⼈试图和新⼈竞争时，发现道路并不连续。

13/ 不连续的原因在于，在新的套路上顺利启航，需要补⾜⼤量功课，投⼊⼤量⼈⼒物⼒，而因为此套路上已经有领先者，回报对于追赶者⽽⾔，是有很⼤不确定性的。如果差距过⼤，⽼⼈⽆法追赶新⼈，这就是进化的死胡同。这好⽐陷在⽶缸⾥的⽼⿏，当⽶的⾼度跌破临界点时，再也⽆法跳出，只能混吃等死。

14/ 在某个局部时间段，两个⼈可能看上去⼀样富⾜，两个公司可能看上去有⼀样的市值；看上去他们似乎差别不⼤，但可能在完全不同的路径上惯性⾏驶，其中⼀个注定要衰败，因为他没有⾜够的资源，从进化的死胡同中爬出。⼆者之间并不连续。

15/ 资本市场，有时给予投资者⼀个很短的时间窗口，可以卖掉衰败的公司，买⼊成⻓迅速的新公司。但⼤部分投资者因为知识⾯和注意⼒的狭窄，没有⾜够敏感强⼤的认知能⼒，没有可能去连续地完成这个转变。

16/ 进化死胡同的悲剧在于，短期内你朝任何⼀个⽅向移动，你看上去都会⽐原来的位置更糟。你的内⼼会抗拒这种转变，⼀个公司内会有⼤量⽼系统内的⼈激烈反对；而任何拖延，只会加⼤新的挑战者和你的差距。

17/ 讽刺的是，⽼套路下越成功，遇到新套路的挑战时，来⾃内部的反对改变的抗拒⼒就越⼤。

18/ 当⼀个群体衡量进步的唯⼀标准是短期的⾦钱收益时，它会想⽅设法避免短期的痛苦转型⻛险，和没有明确收益的⻓期布局。但这种做法恰恰注定了它⻓期的没落。摆脱这种困局的第⼀步，是要改变衡量进展的标准。

# 从编程技术的变迁看程序员的不连续性

1/ 在推特上看到⼀些资深程序员回顾过去三⼗多年编程技术的变迁，⾮常有借鉴意义。

2/ 有⼈说，在 1988 年看，有三样技能对于程序员来说最重要：C 语⾔、图形界⾯编程、⾯向对象编程。

3/ 但没有⼈预测到 1993 年浏览器的出现。1995 年之后，市场上对于会⽤ HTML 编程、会维护 apache server、会写 CGI 程序的需求⼤增。实践中 Perl 和 Python 也是最常⽤的⼯具。Perl 实际上⽐ Python 更流⾏。

4/ 到 1998 年，微软在浏览器上的市场份额越来越⼤，⼀类主流观点是，下⾯三样技能对于程序员最重要：ActiveX、OLE（Object Linking and Embedding）、ATL（Active Template Library）。

5/ 实际操作上，微软的这套技术框架极为复杂繁琐难懂。打个⽐⽅，⽤ ActiveX/OLE 写程序，好⽐放⼀个屁要脱三次裤⼦。ActiveX 还有安全和兼容问题，慢慢很少有⼈⽤，它原来想要实现的功能，都可以轻松被后来的 HTML5/JavaScript 解决。

6/ 还有⼈记得九⼗年代由⼗⼏家公司（惠普、IBM、Sun Microsystem、Apple 等等）不遗余⼒联合推⼴的分布式编程标准 CORBA（Common Object Request Broker Architecture）吗？2002 年后就慢慢销声匿迹了。分布式计算，理论很丰满，实际很⻣感。

7/ 2006 年之后，亚⻢逊悄悄地开始了云计算的建设和推⼴。

8/ 2008 时，⼀类主流观点认为，下⾯三样技能对于程序员最重要：SOAP（Simple Object Access Protocol）、Enterprise Service Bus、AJAX with XML。

9/ 但实践上，AJAX 不适合后来出现的移动编程应⽤，还有各种安全和兼容问题。而 JSON 也远⽐ SOAP 更灵活好⽤。
